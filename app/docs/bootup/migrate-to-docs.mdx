# Migrate to Docs

Learn how to migrate your existing setup to Docs platform.

## Migration Overview

Migrating to Docs is a straightforward process that can be completed in a few simple steps.

## Step-by-Step Guide

<Steps>
	<Step title="Prepare your data">
		Before starting the migration, export your current data, review configuration
		settings, and back up anything critical.
	</Step>
	<Step title="Run the migration tool">
		Use the automated migration tool to transfer your data:

		```bash
		Docs migrate --source your-platform
		```
	</Step>
	<Step title="Verify migration">
		After migration, confirm that records, configurations, and core flows behave as
		expected in staging before you cut over production traffic.
	</Step>
</Steps>

## Common issues

<AccordionGroup title="Migration troubleshooting">
	<Accordion title="Data format compatibility">
		If you see validation errors, compare your export against the expected schema in the
		migration guide and normalize fields (dates, currency, IDs) before retrying.
	</Accordion>
	<Accordion title="Configuration mapping">
		Some legacy settings do not map one-to-one. Note any manual overrides in your runbook
		and re-apply them in the Docs dashboard after import.
	</Accordion>
	<Accordion title="Partial import or timeouts">
		Retry with batching enabled, or run during off-peak hours. If failures persist, open a
		ticket with the failed job ID from the migration log.
	</Accordion>
</AccordionGroup>
